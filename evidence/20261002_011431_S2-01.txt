Test ID: S2-01
Title: Default/weak credential check
Student: student2 (Privacy & Data Leakage Assessment)
Specialization: Authentication Weaknesses

Objective:
Verify /token rejects common default credentials (admin/admin, test/test).

Input / Attack Scenario:
POST /token with username=admin, password=admin.

Expected Behaviour:
401/403 rejection; no token issued.

Actual Behaviour:
{
  "sent": {
    "username": "admin",
    "password": "admin"
  },
  "received": {
    "status": "ok",
    "http_status": 422,
    "headers": {
      "date": "Thu, 01 Oct 2026 19:41:25 GMT",
      "server": "uvicorn",
      "content-length": "154",
      "content-type": "application/json",
      "vary": "Origin"
    },
    "body": {
      "detail": [
        {
          "type": "string_too_short",
          "loc": [
            "body",
            "password"
          ],
          "msg": "String should have at least 6 characters",
          "input": "admin",
          "ctx": {
            "min_length": 6
          }
        }
      ]
    }
  }
}

Observations:
HTTP 422 due to minimum password length; no token issued.

Conclusion:
Default credentials not accepted.

Severity: low
Severity justification: A successful default-credential login is immediate full-system compromise.
